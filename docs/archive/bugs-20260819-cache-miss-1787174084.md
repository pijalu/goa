The event at line 4,756 is the last turn of the previous goal (its content

(prompt_cache_key / previous_response_id / session-affinity) — per the hard
rule that a diverging context must not share the old ID.

## Why this is not counted as a CM bust

`RunFresh(begin=true)` emits `EmitContextReset` → the agent emits
`EventContextReset` → `handleAgentStatsEvent` calls `resetCacheBustBaseline`
(clears `lastTurnCacheRead`, disarms `cacheReadEstablished`). Event ordering
is guaranteed: all agent events flow through the single
`runAgentEventReader` goroutine via `a.apply(...)`, and the reset is emitted
before the first fresh turn's `agent.Run` — so the cold turn is processed
strictly after the re-arm. The cold start is cold by nature and not counted.
Covered by `TestHandleTokenStats_CacheMissFreshContextReset`
(internal/app/stats_cm_test.go).

## Conclusion

No message rewrite, reorder, stale-context resend, or conversation-ID
divergence. The miss signature is the intended cost of the fresh-context goal
boundary; cache hits resume immediately after (72k read on the next turn) and
grow monotonically thereafter. No code change required.
