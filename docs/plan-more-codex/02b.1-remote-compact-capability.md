# Task 2b.1 — Remote-compaction capability + config gate

**Phase:** 2b (Server-side remote compaction) · **Size:** small · **Depends on:** none

## Objective

Add a provider capability + config flag that says "this provider supports server-side
`/responses/compact`", defaulting **off** until validated. No request logic — just detection
and gating, mirroring Codex's `RemoteCompactionSupport` + `Feature::RemoteCompactionV2`.

## Context to load (only these)

- `_shared-context.md` §1 (remote compaction), §2 (compaction engine, compaction policy), §3 (invariants)
- `internal/agentic/compaction_policy.go` (`DecideCompactionPolicy`) — see how strategy availability is fed in
- `internal/agentic/agent_compression.go` (`compressHistoryWith`, strategy selection)
- The provider-capability / model-profile mechanism (search: `SupportsStore`, `VariantProfile`, `Compat`) in `internal/agentic/provider/schema/`
- Codex ref (read-only): `../codex/codex-rs/core/src/session/turn.rs` — `RemoteCompactionSupport` dispatch (≈1183–1238)

## Design constraints

- **Default off**; opt-in via config. Reversible.
- Capability must be **provider/model-scoped**, not global — only Codex-like Responses providers that actually expose `/responses/compact`.
- Pure additive config; existing behavior unchanged when disabled.

## Steps

1. Add a `RemoteCompaction` capability to the provider/model capability set (e.g. none | v1 | v2), defaulting to none.
2. Add a config gate (e.g. `features.remote_compaction`) defaulting to false.
3. Surface "remote compaction available" as an input to the compaction policy/strategy selection (so 2b.2 can prefer it).
4. Wire Codex Responses flavor to report the capability when its endpoint advertises it (or when explicitly enabled).

## Tests

- Default: capability none, gate false → local ladder unchanged.
- Enabled + supported → policy sees remote-compaction as available.
- Enabled + unsupported provider → falls back to local.
- Config parsing/validation tests for the new flag.

## Verify

```bash

```

## Completion criterion

A provider-scoped remote-compaction capability + default-off config gate exists and is visible to the compaction policy, with default behavior unchanged, and the capability/policy tests + vet pass with `-race`.
