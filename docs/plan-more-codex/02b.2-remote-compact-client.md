# Task 2b.2 — Remote `/responses/compact` client + history replacement

**Phase:** 2b · **Size:** large · **Depends on:** 2b.1

## Objective

Implement the unary `POST /responses/compact` call that returns a replacement conversation,
and use it to replace Goa history (advancing cache generation) when the 2b.1 capability+gate
allow — instead of running a local summarization model call.

## Context to load (only these)

- `_shared-context.md` §1 (remote compaction), §2 (compaction engine, cache identity), §3 (invariants 1, 4)
- 2b.1 capability + gate
- `internal/agentic/agent_compression.go` — `compressHistoryWith`, `summarizeHistory`, and history replacement sites (≈172, 343, 1087)
- `internal/agentic/provider/cache_identity.go` (`NewCacheKey`, generation advance)
- Codex ref (read-only): `../codex/codex-rs/core/src/client.rs` — `compact_conversation_history` (552–656), `ApiCompactionInput`; `compact_remote_v2.rs` (`RETAINED_MESSAGE_TOKEN_BUDGET`, `MAX_RETAINED_AGENT_MESSAGE_TOKENS`)

## Design constraints

- Unary (non-streaming) call with its own bounded timeout (Codex multiplies the idle timeout for compact requests).
- Send only what the normal request path already sends (model, input, instructions, tools, parallel_tool_calls, reasoning, service_tier, prompt_cache_key, text). Honor forensic redaction (invariant 4).
- The returned history is a **non-prefix rewrite** → advance cache generation (Phase 3) so the SSE path rotates the key.
- Provenance: record strategy `remote_compact` with before/after estimates and the existing `start → summary → end` triple.
- Failure of the remote call must NOT lose history — fall back to the local ladder (2b.3 formalizes).

## Steps

1. Add a compact client method on the Codex Responses provider that POSTs `ApiCompactionInput` to the compact endpoint and decodes the returned item list.
2. Integrate into `compressHistoryWith` (or the strategy dispatcher): when capability+gate allow, choose `remote_compact` ahead of local summarization.
3. Replace history with the returned items; advance cache generation.
4. Record provenance + before/after token estimates.
5. Apply a retained-message budget mirroring Codex (`RETAINED_MESSAGE_TOKEN_BUDGET = 64_000`) so the replacement stays bounded.
6. On remote error, return a distinct error so the caller can fall back (do not partially apply).

## Tests

- Fake compact server returns a shortened item list → history replaced, generation advanced, provenance triple emitted with `remote_compact`.
- Replacement is bounded by the retained-message budget.
- Remote failure → history untouched, error surfaced for fallback.
- Cache key rotates on the SSE path after replacement.
- Request body carries `prompt_cache_key` and the Codex fields; no secrets in diagnostics.
