# Task 6b.2 — Request-property match + prefix delta computation

**Phase:** 6b · **Size:** medium · **Depends on:** 6b.1

## Objective

Implement the pure decision logic that answers: "can this WS request be sent as an
incremental delta, and if so what is the delta?" No network/transport changes — a pure,
well-tested function operating on the 6b.1 baseline and the candidate request.

## Context to load (only these)

- `_shared-context.md` §1 (WS delta precondition), §3 (invariants)
- 6b.1 output: the `wsSessionBaseline` type in `internal/agentic/provider/openai_responses/`
- `internal/agentic/provider/protocol/openai_responses.go` (`applyCodexBodyFields`, `applyResponsesSessionFields`, `applyResponsesSamplingFields`) — the fields that must match
- Codex ref (read-only): `../codex/codex-rs/core/src/client.rs` — `responses_request_properties_match` (≈308–361), `get_incremental_items` (≈1221–1259)

## Design constraints

- **Pure function**: no mutation, no I/O, no timestamps. Deterministic.
- Mirror Codex's match set: model, instructions, tools, tool_choice, parallel_tool_calls, reasoning, store, stream, include, service_tier, prompt_cache_key, text. Keep it exhaustive so a new field forces an explicit decision.
- The prefix check must be a **strict append** of `last_input + last_response.items_added`, compared item-by-item ignoring internal metadata (mirror `response_items_equal_ignoring_internal_metadata`).
- Prefer reusing the existing Phase 4 prefix classification (`cache_forensics.go`) where it already computes append-vs-divergence, rather than duplicating logic.
- Low cyclomatic complexity: extract the property-match and the prefix-match into separate small helpers.

## Steps

1. Define a `requestFingerprint`-style struct capturing the comparable fields of a built Codex request (reuse the fields the protocol layer sets).
2. Implement `requestPropertiesMatch(prev, cur) bool` mirroring the Codex field set.
3. Implement `computeDelta(baseline, newInput) (delta []schema.Message, ok bool)`:
   - `prevLen = len(lastInput) + len(addedItems)`; if `len(newInput) < prevLen` → not ok.
   - Verify `newInput[:prevLen]` equals `lastInput + addedItems` item-by-item (ignoring internal metadata); mismatch → not ok.
   - `delta = newInput[prevLen:]`; ok.
4. Combine into `decideIncremental(baseline, prevProps, curReq) (delta, responseID, ok)` returning `ok=false` on: no baseline, empty responseID, property mismatch, prefix mismatch, or empty delta when empty deltas are disallowed.
5. Document that a compaction (history replacement) naturally fails the prefix check → forces full send.

## Tests (table-driven)

- Exact append + matching properties → delta + responseID.
- Each single-field property change → not ok (one subtest per field).
- Prefix mismatch / shorter input → not ok.
- Empty baseline / empty responseID → not ok.
- Empty delta allowed vs disallowed flag.
- A replacement history (post-compaction shape) → not ok.
