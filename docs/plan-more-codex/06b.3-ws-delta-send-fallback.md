# Task 6b.3 — Wire delta send path + fallback

**Phase:** 6b · **Size:** large · **Depends on:** 6b.1, 6b.2

## Objective

Make the Codex WebSocket transport actually send incremental deltas chained by
`previous_response_id` when 6b.2 says it's safe, and fall back to full-history SSE
otherwise — without ever breaking the append-only / cache-warmth guarantees.

## Design constraints

- **Cache-key rule (Finding 4 / amended Phase 3):** on the WS-incremental path keep `prompt_cache_key` **session-stable**; do NOT rotate on compaction. The SSE/full-resend path keeps the existing generation-rotation.
- A failed request must NOT advance the baseline (6b.1 already guarantees this; preserve it).
- Never send a delta across a compaction generation boundary — the prefix check (6b.2) already fails there; assert it.
- SSE path must remain byte-identical to today (invariant 3).
- The current low-level `WebSocketTransport.Do` is **one-shot** (no persistent connection reuse). Do NOT attempt Codex-style multi-request connection pooling in this task; that is a follow-up. Delta-over-one-shot-WS is still correct and is the deliverable.

## Steps

1. In the Codex WS request path, before building the body, call `decideIncremental`.
2. When `ok`: build the body with `input = delta` and set `previous_response_id = responseID`; keep all other matched fields identical to the matched prior request.
3. When `!ok`: build the full-history body exactly as today; if the transport previously fell back (e.g. `UPGRADE_REQUIRED` or a prior WS failure), use SSE.
4. Route the send through the existing WS transport; on transport-level failure that indicates WS is unsupported, mark the session for HTTP/SSE fallback (per-session only, not global) and retry as full-history SSE with identical intent.
5. Ensure retries never reuse a partially divergent request or a stale `previous_response_id` (a retry rebuilds from `decideIncremental` against the current baseline).
6. Keep authentication/Codex headers on the provider-specific path; no auth logic in the shared transport.

## Tests (deterministic fake WS/SSE server)

- Multi-turn Codex conversation: turn 1 full send; turns 2+ send delta + `previous_response_id`.
- A property change mid-session → next request is a full send.
- A compaction mid-session → next request is a full send (no delta across generation).
- WS-unsupported response → per-session SSE fallback, other sessions unaffected.
- Failed request → baseline not advanced; subsequent request retries correctly.
- `prompt_cache_key` identical across the whole WS delta sequence.

## Completion criterion

Codex WS sends delta + `previous_response_id` on exact append with matching properties, falls back to full-history (WS or SSE) on any mismatch/failure/compaction, keeps `prompt_cache_key` session-stable on the WS path, leaves SSE bytes unchanged, and the fake-server suite + vet pass with `-race`.
