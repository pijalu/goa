# Task 2b.3 — `fresh_window` (no-summary) mode + local-ladder fallback ordering

**Phase:** 2b · **Size:** medium · **Depends on:** 2b.2

## Objective

Add Codex's `TokenBudget`-style **fresh-window** compaction — install a new context window
with **no summarization call at all** — as a distinct, cheapest strategy, and formalize the
full strategy ordering: remote compact → fresh_window → local ladder (prune → micro →
selective → summarize) → emergency.

## Context to load (only these)

- `_shared-context.md` §1 (remote compaction, TokenBudget mode), §2 (compaction engine, compaction policy), §3 (invariants)
- 2b.2 remote compact client
- `internal/agentic/compaction_policy.go` (`DecideCompactionPolicy`)
- `internal/agentic/agent_compression.go` (`compressHistoryWith`, `dropOldestToFitLocked`, `pruneToolResultsPreCompact`, strategy selection)
- Codex ref (read-only): `../codex/codex-rs/core/src/compact_token_budget.rs` (whole file, ~93 lines)

## Design constraints

- `fresh_window` is **cheaper than any summarization** (zero LLM calls); expose it as a config-selectable strategy.
- It is still a compaction: emit the same lifecycle/provenance events so hooks and observers see a consistent contract (Codex models it as a normal compaction lifecycle).
- Because it discards history, it must advance cache generation and respect invariant 1 (it is an *explicit* compaction boundary, not a mutation of sent messages).
- Keep the existing least-destructive local ordering intact as the fallback when remote/fresh_window are not selected.

## Steps

1. Add a `fresh_window` (a.k.a. token-budget) strategy to the compression strategy enum/config.
2. Implement it: start a new context window (keep system + configured recent-turn/last-user preservation), emit the compaction lifecycle events, skip any summarization call.
3. Advance cache generation; record provenance with strategy `fresh_window`.
4. Order strategy selection: remote_compact (if capability+gate) → fresh_window (if configured) → local ladder → emergency.
5. Keep `DecideCompactionPolicy` a pure four-way decision; the new strategies are *strategy* choices within a `HighMarkCompaction`/`EmergencyFallback` decision, not new decision kinds.

## Tests

- `fresh_window` compacts with **zero** summarization calls and emits the lifecycle/provenance events.
- Cache generation advances; SSE key rotates.
- Ordering: with remote available it wins; without it fresh_window (when configured) beats local summarize.
- Local ladder unchanged when neither remote nor fresh_window is selected.
- Config validation for the new strategy.
